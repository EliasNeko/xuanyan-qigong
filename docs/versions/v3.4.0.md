# v3.4.0 — 认账版：页面说完成就立刻停，不跟你的进度条抢

发布日期：2026-11-19

## 为什么改

v3.3.0 之后连着暴露了同一类问题：**任务点已经绿了，脚本还在陪着放那个视频**，用户三次截图三次投诉：

- 「明明显示已完成的视频还在观看，我手动拉进度条才到下一任务点」
- 「又在重复播放了，这次我手拉进度条还甚至给我倒回去重放」
- 「这个视频下面还有一个未完成视频和讨论链接，居然还在播那个已完成的」

根因查出来是三条，全在细节上：

1. **完成检测找错了地方**。脚本一直在「视频所在的那个 iframe」里找「任务点已完成」，可学习通把这行字写在**父页面**里（视频在 v.chaoxing.com 的 iframe 内）。这条检测从上线起就没命中过。
2. **保活把用户的操作顶掉了**。播放循环每秒发一次 play()，你按暂停、拉进度条，下一秒就被脚本拽回来；卡住的分支还会把进度**往回退 3 秒**再播。
3. **同一个视频被收集了两遍**。iframe 里一份、镜像/预加载又一份，「这段播完了」就去找第 2 段，播的还是同一条。

## 改了什么

- 新增 page_says_done(page)：遍历**所有 frame**，并且穿透 shadow root 去读文字，再兜底认 job-finished / yiwancheng / icon-finished 这类类名。页面说完成就认。
- 判定从「连看两次 + 播过 8 秒」改成「**播过 5 秒后，页面说完成就立刻停**」。残留文字只可能出现在切任务点后那一两秒，5 秒足够挡掉。
- 页面说完成 → **立刻停播、不换别的视频**。以前这里会「换到下一个视频接着播」，用户看到的就是「已完成的还在放」。剩下的交给下一张任务点卡片（讨论区也一样走卡片）。
- 每段视频收工（done / blocked / stuck / timeout）都调一次 pause_all_videos(page)：整页所有 video 全按停，不许有任何一段还在放。
- 新增 soft 保活：视频上带着「用户操作过」的标记（xy-act=user）且处于暂停态时，脚本**不碰**它。你暂停就暂停，你拉进度条就按你的位置放。
- 卡住分支：看得出是你手动操作的就只等，**不再往回 seek**。
- 你手动把进度条拉回去不算「播放器重播」，不计重播次数、不因此暂停、不判完成。
- 视频按「地址 + 时长」去重，同一个播放器只播一次。
- 章节测验去掉「做得太快，等 N 秒再交」：只留 2~6 秒的「再核对一遍」就提交（用户原话：「为什么在这里停着不提交了，还是在等时长？？？」）。
- 认「被拦」更准：BLOCK_WORDS 扩到 操作异常 / 操作行为异常 / 请求过于频繁 / 拖动下方滑块 / 请输入验证码，目录页、文档页、视频页都会看一眼；命中就停手等人工，不刷新、不重试。

## 怎么验证

- python -m compileall -q learn_auto / python -m pyflakes learn_auto 干净，无 undefined name。
- 三个内嵌 JS（VIDS_JS / DONE_TEXT_JS / PAUSE_ALL_JS）都过了一遍 node --check。
- 打包（PyArmor 9.3 + PyInstaller）产物 ProductVersion 3.4.0.0；LEARN_AUTO_SELFTEST=1 自检通过：TITLE 用户登录 / URL https://passport2.chaoxing.com/login?fid=&refer= / OK。

## 升级

覆盖安装即可，config.json、进度、答案库都留在原处。

## 还留着的问题

- 有的任务点（纯图片「明要点」）网页端根本不上报完成，脚本只能标「需要人工」。
- 某些视频要求「真人观看」，播到 91% 也不认 —— 现在最多陪一遍，播完记住、下一轮再判。
- 每节结束后回到目录页偶发加载失败（章节树读到 0 个），已加「歇几秒重开一次」，但网络很差时仍可能跳过一节。
