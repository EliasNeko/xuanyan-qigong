# v2.1.2 — 修复版：视频看完就收工，章节测验被漏掉

发布日期：2026-11-19

用户报的现象很直接：一个小节里明明有「视频 + 章节测验」两个任务点，
脚本把视频播完就转下一节了，测验一次都没打开过。查下来不是测验判错类型，
而是脚本压根「看不见」它 —— 读任务点的办法只盯着页面上已经渲染出来的那一个。

## 为什么改

学习通的小节页默认只渲染**当前选中**的那个任务点容器，其余任务点只是标签条
（`#prev_tab` 里的 `li`）上的一行字。v2 重置版把「先视频再测验」的写死流程换成
「进小节现读卡片」之后，读卡片用的是 `chapters.cards_state()`，它扫的是
`.ans-job-icon` —— 也就是**已经渲染出来的容器**。所以：

- 刚进小节时只有视频容器存在 → 卡片表里只有「视频」，播完 `unfinished` 为空，收工
- 标签条上的「章节测验」从头到尾没进过列表，自然从来没被点开

真机抓下来的对比很直观：`cards_state` 只有 1 条（视频，已完成的 `ans-job-video`），
而 `task_points`（读 `#prev_tab li`）有 2 条，`unfinish=1`。

顺带还发现一个更隐蔽的问题：点任务点标签用的那段 JS 写成 `() => {…}`，
却在函数体里用 Playwright 传进来的 `name` —— 形参没声明，`name` 静默取到
`window.name`（空串），于是 `indexOf("")` 恒为 0，**点中的是页面上随便一个元素**。
平时它表现的像是「点了但没反应」，很难往这边想。

## 改了什么

- **任务点全集改成「标签条 ∪ 已渲染容器」**：以 `#prev_tab li` 为准，逐个和页面上
  已渲染的容器合并。匹配按三级来：容器标题等于标签标题；`active` 标签认领没有标题的
  容器（点开某个任务点后容器往往没有标题）；按类型认领（视频标签 ↔ `ans-job-video`
  容器，这样切到测验页、视频容器被卸载时还能记住它已完成）。容器没标题时用标签名补上。
  标签条上 `unfinish == 0` 时全部算完成；渲染了却没在标签条里的容器额外追加，不丢。
- **点标签按名字点**：`TAB_JS` 改成 `(name) => {…}`，名字去空白后为空直接返回 0，
  不再「空名字命中一切」。
- **本节内记住已确认完成的任务点**：切到测验以后视频容器会被卸载，光看页面就变成
  「没渲染 = 不知道」，下一轮会把视频重做一遍。现在按任务点名记一份，回填 `finished`。
- **测验没读到题目不再算完成**：`res.total == 0` 时标 `quiz_missing`，外层把这一节
  记成 `partial`（「测验页没读到题目」）而不是 `done`，避免「没答也算做完」。
- 试填模式（`quiz.dry_run`）填完就停在本节，不再原地重试好几轮。

## 怎么验证

- 新增 `tests/test_cards_merge.py`：用 Playwright + 假 DOM 复刻「只渲染视频容器、
  标签条有两条」的场景，五个用例覆盖：卡片表两条都在、切到测验后列表不变、
  测验做完判完成、`unfinishCount=0` 时全完成、`click_tab("章节测验")` 真按名字点中
- `tests/test_taskpoint.py`、`tests/test_chain.py` 仍全过
- `pyflakes` 扫全部模块：0 个 `undefined name`
- 真机跑一个小节（《深邃的世界：西方绘画中的科学》·「现代设计中的黄金分割」，
  视频 + 章节测验）：日志依次出现「本节任务点 2 个」「切换任务点: 章节测验」
  「★ 章节测验共 4 题」，4 题全部选中（题面被字体加密，用 `font-cxsecret` 还原）；
  用试填模式验证，没有替你提交

## 升级

直接覆盖安装（或解压免安装包替换目录），`%LOCALAPPDATA%\LearnAuto` 里的登录态、
题库、进度、截图都保留。

## 还留着的问题

- 讨论、问卷、直播类任务点不代做（会识别出来并跳过）
- 填空 / 简答 / 计算靠模型现编，答得对不对看模型；连线、主观论述仍无解
- 测验页若有题目既没有选项也没有输入框（连线题之类），那几道会被跳过，交卷后可能不满分
