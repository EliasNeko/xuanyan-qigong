# v1.0.1 · 2026-11-18

## 一句话

修掉了「明明刷过好几节，重跑又从第一节开始」这件事：现在打开就知道哪几节已经做完了，直接接着刷没做完的那节。

## 这次改了什么

| 位置 | 改动 |
|---|---|
| 章节树扫描 | 除了原来的待完成徽章，再读每个小节自己的未完成任务点数（`input.jobUnfinishCount` / `input.knowledgeJobCount` / `.catalog_points_yi`），三处任何一个说「0 个待完成」就当这节已经做完 |
| 选下一节 | 服务端说做完的小节直接跳过，不点开、不重看视频、不重答一遍 |
| 本地进度 | 扫到的「服务端已完成」会补记进本地进度，换电脑 / 重装程序后照样能接着跑 |
| 代码结构 | 这段判断单独放进 `tree.py`（发布用的加密工具对单文件体积有上限） |

## 真机验证

同一门课、同一个账号：35 个小节里认出 9 节已完成（1.1~4.2 与 5.1），`pick_next` 直接给出 **5.2「维纳斯的传说」**，而不是回到 1.1。

## 升级方式

重新运行安装包即可（会覆盖程序本体，登录态与配置保留）。已经刷过的任务点在服务端，升级不会丢。

## 已知问题（没变）

- 章节测验的答案来自「本地题库 + 豆包网页版」，判断题与教材口径不一致时会错，分数不保证 80 以上。
- 交过且没过线的测验，若页面没有重做入口，分数改不了（脚本不代按重做）。
- 视频任务点是否完成以 `.ans-job-finished` 图标与服务器未完成数为准；服务器记账有几秒到几十秒延迟，所以 91% / 96% 各问一轮。
