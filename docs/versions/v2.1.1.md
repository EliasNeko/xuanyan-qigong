# v2.1.1 — 修复版：点开任务点就崩的两个 bug

发布日期：2026-11-19

v2.1.0 发出去当天就接到报错：一进小节、刚点开第一个任务点，界面就不动了，
日志里只有一段 traceback。查下来是 v2 重置重构时漏掉的两处引用 —— 功能其实都在，
但一按就停，等于不能用，所以当天补一版。

## 为什么改

v2.1.0 把「先视频再测验」的写死流程换成了「进小节现读卡片、逐个类型做」，
新写的两个小函数在合并时各丢了一行：

1. `taskpoint.card_done_checker()` 本来该返回一个「这个任务点完成没」的回调，
   结果内部 `check()` 写完后忘了 `return check`，函数返回 `None`。
   调用处 `done_check()` 于是抛 `TypeError: 'NoneType' object is not callable`
   （`taskpoint.py` 里做任务点的那一段）。
2. 外层 `runner._run_course()` 的异常处理想判断「是不是用户把浏览器窗口关了」，
   调了 `_browser_closed(exc)`，但这个函数的定义没跟过来，于是真正的错误被
   `NameError: name '_browser_closed' is not defined` 盖住，看起来像别的问题。

两次都是「名字在、定义没了」，加密打包不会报错（运行到那行才炸），所以 v2.1.0
的自检（只打开登录页）也没抓到。

## 改了什么

- 给 `card_done_checker` 补上 `return check`，任务点完成判定恢复
- 在 `runner.py` 里补回 `_browser_closed(exc)`：认 Playwright 的
  `TargetClosedError` / `BrowserClosedError`，以及 `target closed`、
  `connection closed` 这类文案；命中后按「窗口被关了、进度没丢」收尾，不再甩 traceback
- 顺手修两处同类问题（都是 v2.1.0 重构带出来的）：
  - `aichat.py` 的 AI 文字答案日志用了没导入的 `short`
  - `ui_kit.py` 磨砂卡片备用绘制路径里高斯模糊半径 `blur` 没定义（现在默认 4.0）

## 怎么验证

- `pyflakes` 扫全部模块：修复前 3 个 `undefined name`（`short`、`check`、`blur`），修复后 0
- `card_done_checker(page, card)` 返回可调用对象；`_browser_closed()` 对
  「Target page, context or browser has been closed」判 True、对普通异常判 False
- `tests/test_chain.py`、`tests/test_plan_queue.py`、`tests/test_pace.py` 全过
- 重新 PyArmor 加密打包，`LEARN_AUTO_SELFTEST=1` 自检通过（TITLE 用户登录、OK）

## 升级

直接覆盖安装（或解压免安装包替换目录），`%LOCALAPPDATA%\LearnAuto` 里的登录态、
题库、进度、截图都保留。

## 还留着的问题

和 v2.1.0 一样：

- 讨论、问卷、直播类任务点不代做（会识别出来并跳过）
- 填空 / 简答 / 计算靠模型现编，答得对不对看模型；连线、主观论述仍无解
- 题目被字体加密、题干读不出来时，测验可能一道道都答不上，脚本会停下提醒
