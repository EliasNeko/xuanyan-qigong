# v3.2.0 — 完成判定版：页面说做完就是做完了，讨论也会替你回

发布日期：2026-11-19　·　构建：PyArmor 9.3 + PyInstaller　·　安装包 3.2.0

## 为什么改

v3.1 之后被同一个毛病抓了第四次：**任务点早就显示「已完成」，脚本还在那儿陪着看视频。**
翻回去看判定代码才明白根子在哪 —— 它拿「本节还剩几个没完成」当答案，
只要这一节还有别的任务点没做，手上这个做完了也一样返回「没做完」，于是继续播、继续等。
另外两类任务点也一直是空的：

- **讨论**：读老师给的材料 → 按要求写一段 → 发在话题下，才算完成。以前脚本直接跳过，
  你自己手动回过了它也认不出来；
- **直播 / 签到**：真的需要人到场，脚本不该假装能做，但也不该和「暂时还不支持」混在一起提示。

## 改了什么

### 1. 完成判定重写成四层，从上到下越问越细

`learn_auto/tp_done.py` 整个重写，`DoneTracker` 现在的顺序是：

| 层 | 问什么 | 代价 |
| --- | --- | --- |
| ① 页面 | 容器带 `ans-job-finished` / 图标 `aria-label` 说已完成 / 绿字「任务点已完成」 | 白问，随便问 |
| ② 基线 | 做这个任务点**之前**服务器还剩几个，做完再问，数量掉了就是它做完了 | 每 6 秒最多一次 |
| ③ 归零 | 本节 `unfinishCount == 0` → 整节做完 | 同上 |
| ④ 都没有 | 才认为真没做完 | — |

关键是 ② 这个 `_base` 基线：把「本节还剩几个」换成「这一个做完了没有」，
同一节里其它没做的任务点不会再把判定拖死。

### 2. 页面怎么认「已完成」：三路信号取并集

`learn_auto/pagesrc.py` 的 `job_boxes()` 现在从 `.ans-job-icon` 往上最多五层找容器，
同时看三个地方：

- 容器 class 里有没有 `ans-job-finished`；
- 图标 class 里有没有 `finished / completed / done`；
- 图标 `aria-label` —— 先判「未完成」（含「未完成」三字直接假），再看有没有「已完成」；

外加一条 `done_text()`：整页里出现「任务点已完成」这种绿字时，认它是**当前活跃那一个**做完了。
（起因是实测：7 个全都做完的任务点里，4 个视频的 `aria-label` 还写着「任务点未完成」——
光看 aria 会漏一半，所以只把 aria 当其中一路证据。）

`tp_scan.list_cards()` 把三路合成一个状态：`completed` / `incomplete`（有图标但没完成）/ `unknown`（连图标都没有）。

### 3. 播放循环每 3 秒自查一次，页面认了就别看了

`learn_auto/player.py` 的 `watch()` 多了一个 `on_tick` 回调，循环里每 3 秒问一次
「这个任务点是不是已经完成了」：

```python
# learn_auto/player.py:241
if on_tick is not None and time.time() - last_tick >= 3.0:
    last_tick = time.time()
    if on_tick():
        frame.evaluate(PAUSE_JS)
        return {"status": "done",
                "note": "页面早就标了完成，没看完也收工",
                "watched": int(time.time() - start), "reached": True}
```

所以那种「上一个视频播完、服务端立刻记了完成、页面已经亮绿」的情况，
最多 3 秒就会收手，不会再把下一段视频从头看一遍。

### 4. 讨论任务点：进话题 → 写一段 → 发出去

新增 `learn_auto/discuss.py`（7.4 KB）：

- 读话题：`.topicDetail_title` / `.topicDetail_detail`（新版 groupweb）和
  `div.oneDiv` / `div.content`（旧版 bbscircle）都认，读不到就点第一条话题进去再读；
- 写回复：把标题 + 正文交给 AI，要一段 120~200 字、像学生自己写的话（不分点、不加小标题）；
- 找输入框：`textarea` 或 `[contenteditable=true]`，都没有就点「回复」按钮把编辑器叫出来；
- 填：`value` + 派发 `input / change / keyup`（Vue 那套要事件才认）；
- 提：`.addReply`（新）/ `input.grenBtn`（旧），再按文字「回复 / 发表 / 提交 / 确定 / 发送」兜底；
- 提完让完成判定再复核一次，`confirmed` 才记账。

AI 不可用的时候**默认不发**（宁可留给你手动回，也不往讨论区灌模板话），
想让它硬发可以打开 `discuss.allow_template`。

### 5. 直播 / 签到单独一条提示

以前所有没做的类型都进同一条「脚本不代做」的警告，现在 `live` 类单独说清楚：
「这是直播 / 签到类任务点，脚本没法替你到场，跳过（要人真的在位）」。

## 还留着的问题

- **讨论回复的质量看模型**：写得出人话，但和老师给的材料的贴合度不如你自己写；
  介意的话把「用豆包答题」关掉，脚本就不会往讨论区发东西。
- **直播 / 签到仍然不做**：这类任务点靠的是人到场，脚本没有代签的方案，也不打算做。
- **问卷 / 投票**类任务点目前归在 `live` 里跳过，还没有专门的填写方案。
- 页面说完成的三路信号依赖学习通现在的 DOM；哪天它换皮，这一层要跟着改。
