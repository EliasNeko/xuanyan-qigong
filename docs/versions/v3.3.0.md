# v3.3.0 — 不硬顶版：多视频一个个播，验证码只认一次，撞上风控就停手

发布日期：2026-11-19　·　构建：PyArmor 9.3 + PyInstaller　·　安装包 3.3.0

## 为什么改

v3.2 之后跑真实课程（「通用职业素养」，29 节 / 131 个任务点）又攒了一堆现场问题，这一版几乎全是被实际页面顶出来的：

- **一个任务点挂多段视频**：上一段播完、下一段（或者下一个视频任务点）就在同一页里，脚本却总回去播第一段，后面的永远不动 —— 用户盯了两次都是这个症状；
- **视频早就绿了还在播**：页面写着「任务点已完成」，播放循环还在那儿陪着，风扇跟着起飞。根因是只信 video 元素上的 `finished` 标记，而新版 mooc2 那上面从来不标；
- **验证码**：学习通登录和刷课途中都会弹图片验证码。脚本以前要么干等你手输，要么（更糟）自己认错了还反复提交 —— 用户原话是「我手动输入被脚本覆盖了」；
- **风控**：1.25 倍速 + 快速点来点去，学习通直接甩「操作异常」页面；再撞狠一点，接口全线返回 `{"error":"invalid_verify"}`（要求验证码），这时候再重试只会更紧；
- **白等**：只有一张图的「明要点」任务点，网页端根本不记完成，脚本干等 200 秒；读文档遇到停止也非要等满 240 秒才理人；
- **风扇**：监视屏 0.4 秒重绘一次、播放循环每轮扫全部 frame 找 video，CPU 一直顶在高位。

## 改了什么

### 1. 多视频：按 DOM 顺序一个个播，谁没完播谁

`learn_auto/player.py` 的播放循环重写了挑视频的部分：

- `_frames_with_videos(page)` 穿透 shadow DOM、跨 frame，把页面上**所有** video 按 DOM 顺序收集；
- `_pick(page, cur)` 从当前这一段往后找「容器没标完成」的第一个；
- `_next_pending(page, skip=cur)` 在当前这段已标完成时，找**还有没播完的**那一段，直接换过去；
- 换段时不再 `page.bring_to_front()`，也不再乱点页面 —— 你在别的窗口干活不会被抢焦点。

### 2. 页面说完成就停播（去抖后才认）

每 3 秒看一眼页面的 `DONE_TEXT_JS`（匹配 `任务点已完成` 那行绿字）：

- 还有没播的视频 → 停掉当前这段、换过去（`_next_pending`）；
- 一段都没剩 → 暂停并返回「页面早标了完成，没看完也收工」，交给下一类任务点。

**去抖**：刚打开一节、或刚切到另一个任务点的那几秒，页面可能还挂着上一个任务点的「任务点已完成」。所以要求「连看两次（约 6 秒）+ 这段真的播过 8 秒以上」才算数，不会把没看的视频当成已完成跳过去。

播放器偶尔会自己从头重播一次（这是学习通记观看时长的机制）。现在会记住每个视频的上一个位置，「时间突然倒回去 + 回到开头」记一次重播；重播满 2 次还没被记完成，就当它播完收工（多半是要人脸抓拍，脚本不该硬耗）。

### 3. 验证码：自己认一次，认不出来就彻底停手

直白说结论：**脚本不会去猜验证码。** 反复提交错答案是最容易招风的动作，而且会把你手输的正确内容盖掉（用户实测踩过）。

- 新增 `learn_auto/ocr.py`：借 Windows 10/11 自带的 OCR 引擎（Windows.Media.Ocr，经 `winsdk` 调用），不联网、不下模型。识别前先放大 5 倍 + 二值化 —— 学习通验证码只有 30 来像素高，Windows OCR 直接认是 0/6，放大后能到 5/6；
- `player.wait_captcha_answer()`：**一张图只认一次**。认对就继续；认错就打印「认得不对（这张图太花了）—— 不再重试，换成你来输」，并**彻底关掉自动识别**（`can_ocr = False`）；
- `player.user_typing(page)`：只要可见输入框里已经有你打的字（≥2 个字符），脚本一个字都不碰；
- 等验证码期间脚本完全停手：不刷新、不点击、不填框，还把验证码截图路径写进监视屏，心跳报的是 `captcha`（看门狗按 15 分钟算，不会以为卡住把这一节重开）；
- 登录页要验证码时也走同一条路（`onboard._do_password` → `player.solve_captcha_once()`），认一次、认不出就交给人 —— 不再是「每次都你自己来」。

### 4. 撞上风控：认怂，不硬顶

- 播放循环里看到「操作异常 / 操作行为异常」：立刻把倍速退回 1.0、暂停、歇 90 秒、刷新这一页再来，重置卡住计数（以前是一直硬顶到看门狗放弃）；
- `courses.list_courses()` 收到 `invalid_verify`：这说明这个 IP 已经被要求验证码了。不打接口了，直接把响应里的 `verify_path` 在浏览器里打开，日志写清「输一次把风控过掉；过完再点开始刷课」，脚本一步不动。

### 5. 不再白等、不再无限重试

- `taskpoint.image_only()`：任务点里只有图片、几乎没字（`img.img_pic` 之类）→ 网页端压根不上报，最多等 70 秒就放过，标「需要人工」；
- `taskpoint.read_doc(..., stop=...)`：读文档时收到停止立刻退出，不再等满 240 秒；
- `runner.Progress.mark()` 现在记 `attempts`：同一节失败两次就标「待补」换下一节，以前 `max_tries` 永远收不到计数，失败小节会无限重来；
- 视频看完但页面还有讨论 → `taskpoint.has_discuss()` 认出来，交给 `discuss.run()` 回一条再算完成。

### 6. 省电

- 监视屏刷新 0.4 秒 → 1 秒（`monitor_ui.py`）；
- 播放循环 15 秒才重扫一次 frame 找 video（原来是每轮都扫）；
- 截验证码只截验证码那张图，不再整页截图。

## 怎么验证的

- `python -m pyflakes app.py learn_auto pack`：0 个 undefined name（加密打包抓不到这类错，打包前必跑）；
- 离线测试全绿：`test_chain` / `test_plan_v3` / `test_plan_queue` / `test_pace` / `test_cards_merge` / `test_pump`；
- 三个新 JS（`DONE_TEXT_JS` / `DISCUSS_BLOCK_JS` / `USER_TYPING_JS`）在 headless 浏览器里逐条跑过：完成文字在 → True、清掉 → False；有编辑器 → `editor`；输入框空 → 0、填字 → 4；
- OCR：合成 4 位验证码 6 张，原图 0/6，放大 5 倍 + 二值化 5/6；
- 加密打包 + 自检：`LEARN_AUTO_SELFTEST=1` 退出码 0，`selftest.txt` 里 `TITLE 用户登录 / URL https://passport2.chaoxing.com/login / OK`；
- 装好版里确认 `winsdk` 跟着 `_internal` 一起进去了（`ocr.ready() == True`）。

## 升级

覆盖安装即可（`%LOCALAPPDATA%\\玄眼奇工`），`config.json` 不会被覆盖。

注意：因为带上了 Windows OCR 所需的 `winsdk`，安装体积比 v3.2 大 40 多 MB。

## 还留着的问题

- 只有一张图的「明要点」任务点，网页端**不产生任何完成上报**（实测 200 秒内零请求），脚本只能标「需要人工」，得你自己点一遍或等平台修；
- 学习通的风控是按 IP + 账号算的。被要验证码时脚本会停手，但**过验证这一步只能人来**；
- 视频最后 10% 偶尔要靠播放器自己重播才被记完成，脚本会给两次机会，两次都不行就放过这一段。
