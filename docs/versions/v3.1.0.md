# v3.1.0 — 读页面源码认任务点：多视频、考试卷、数学题、空课直说

发布日期：2026-11-19

v3.0 把「一整门课能不能不用管地刷完」跑通了，但用户的真实课程一上来就碰壁：
一个任务点里连着两个视频只播了一个、早就做完的任务点还在播、期中期末这种纯试卷的任务点
根本没人管、应用数学里的计算题既点不了也填不上、有的课目录一片空白。

这一版换了个更笨也更稳的办法：**不猜 DOM 的中间状态，直接把整页源代码读下来自己解析** ——
就是 F12 里「查看网页源代码」那一份。于是任务点有几段视频、这一节到底还剩几个、试卷在哪、
题目要几个空，都能从同一份 HTML 里读出来。

## 为什么改

用户的五条原话（大意）：

- 「一个节点里可能有多个视频，上一个视频，下一个任务点还是视频，脚本没检测出来」
- 「实时检测当前任务点是不是所有内容都完成了，有些做完的还在播视频不转下一个」
- 「期中期末这种纯测试任务点没兼容」
- 「数学题做不了，应用数学那种不给写不给选」
- 「空目录的课程要提示『本门课程没有任务点或没有目录』」

外加一条思路：**加一个实时抓页面源代码的能力**，很多判断都可以依赖源码，而不是依赖一堆容易过期的选择器。

## 改了什么

### 1. 新增 `pagesrc.py`：自己读页面源码

`page.content()` 拿整页 HTML（含所有子 frame），用标准库 `html.parser` 手搓一个只有
`tag / attrs / kids / parent` 四面墙的轻量 DOM —— **不引入 bs4 / lxml**，安装包体积和启动速度都不受影响。

在这份文档树上，能用正则或属性直接回答的问题都变成了一行代码：

```python
src = pagesrc.snapshot(page, ttl=1.2)   # 1.2 秒内复用同一份，避免反复读页
src.job_tabs()    # 任务点标签条：标题 / cardid / 是否 active / 是否已完成
src.job_boxes()   # 内容区容器：类型 class、是否 ans-job-finished、cardid
src.cardcount()   # 本节任务点总数
src.unfinish()    # 服务器说这一节还剩几个没完成（unfinishCount）
src.empty_hint()  # 「暂无任务点 / 本节暂无」这类提示
src.exam_entry()  # 「开始考试 / 继续考试」入口
```

> 为什么不用选择器等页面渲染完再问：学习通的标签条和内容区是**分两批**渲染的，
> 中间那一小段时间里 `list_cards` 只能看到一半，旧版就是在这里误判「这节做完了」。

### 2. 任务点识别重做（`tp_scan.py`）

类型判断从「看见关键词就算」改成有序规则，**考试排在测验前面**（「期末考试」也含「考试」二字）：

```
exam  → ans-job-exam / 期末考试 / 期中考试 / 结课考试 / 期末测验 / 单元测试 / 补考
video → ans-job-video / 视频
quiz  → ans-job-work / 章节测验 / 测验 / 作业 / 习题
doc   → ans-job-doc / pdf / ppt / 文档 / 资料
discuss / live → 只认出来，不代做
```

`_claim()` 负责把「标签条上的任务点」和「内容区的容器」配成对，五级顺序：
`cardid` 一致 → 标题一致 → **按位置且类型一致** → 当前 active 且容器没标题 → 同类型兜底。
配不上的多余容器不单独成卡，而是并进同类型宿主任务点的 `parts` 里 ——
**只要其中一份没完成，宿主就是没完成**。这就是「一个任务点挂两个视频」的识别方式。

### 3. 一段播完接着播下一段

视频分支不再「播一次就收工」，而是最多连播 `run.video_rounds`（默认 3）段。
判断「是不是还有下一段」靠一个签名，**故意不含播放位置**，所以同一个视频播完不会被误认成新的一段：

```js
// VIDEO_SIG_JS：src 尾部 + 时长
{ sig: src.slice(-70) + '#' + (video.duration || 0), d: duration, t: currentTime, ended }
```

播完先等 `playback.seg_gap`（默认 2 秒）再抓签名 —— 学习通换源有延迟，抓太快会以为还是上一段。

### 4. 实时复核：这个任务点到底做完没（`tp_done.py`）

三层判断，从便宜到贵：

1. 页面上任务点容器的 class 里已经有 `ans-job-finished` → 直接算完成；
2. 否则每 `run.check_gap_sec`（默认 6 秒）最多问一次服务器：重新读一遍页面源码里的 `unfinishCount`；
3. 服务器说 0 个未完成 → 完成；还没到间隔就沿用上一次的结论，不打断视频。

**每个任务点做完还会强制复核一次**（不等 6 秒窗口），所以「早就做完的节还在播」这种情况
在这一版会在进入下一个任务点之前就被纠正。

### 5. 期中期末这类试卷任务点（`exam_paper.py`）

纯考试类任务点以前会被当成普通测验，结果连题目都读不到。现在单独一条路：

点「开始考试 / 继续考试 / 参加考试」→ 勾「我已阅读并同意」→ 等题目渲染 →
复用测验那套答题链（题库 → 豆包 → 填空通道）整卷作答 → 交卷 → 读分。

考试常常**另开一个标签页**，所以进入前后都比对 `page.context.pages`，
交完卷再把原来的课程页 `bring_to_front` 拉回来，队列才接得下去。

### 6. 数学题（`mathkit.py`）

数学题和文科题的区别不在题面长短：

- **识别**：命中「求 / 计算 / 解方程 / 极限 / 导数 / 积分 / 矩阵 / 概率」这类词，或带 `= ≤ ∑ ∫ √` 这类符号，或整句就是个算式；
- **作答**：给 AI 的提示词换成「只要最终答案，不要过程，分数写 1/2，多空用分号隔开」；
- **还原**：AI 吐的 LaTeX 压成能填进输入框的纯文本 —— `\frac{1}{2}` → `(1)/(2)`，`\sqrt{2}` → `sqrt(2)`，去掉 `$`、`\left`、`\right`；
- **多空**：题干里数出几个空（`____`、`（ ）`、`[ ]`），答案按 `;`、换行、`、` 拆开逐个填。

### 7. 空目录的课直说

`plan.build()` 会给每门课带上 `empty` 标记，空的课程单独收进 `empties`。于是三处都能说清楚：

- 抓目录时日志写：「「马克思主义基本原理」没抓到任何章节：本门课程没有任务点或没有目录」；
- 点「开始刷课」而队列是空的 → 弹窗直接列出是哪几门课没抓到章节，并提示重新抓取 / 去学习通确认；
- 监视屏上写：「队列是空的：这门课没有任务点，或者都已经做完了」。

### 8. 文档任务点不再空转

滚动阅读时如果**连续两轮滚不动**（到底了、或者页面本来就不需要滚），立刻判定读完，
不再硬耗满超时时间 —— 一个文档任务点以前可能白等几十秒。

## 升级

覆盖安装即可，`%LOCALAPPDATA%\玄眼奇工` 里的 `config.json`（登录态、题库、进度、截图）不会被替换。
想调新参数可以在 `config.json` 里加：

```json
{
  "run": { "video_rounds": 3, "check_gap_sec": 6.0 },
  "playback": { "seg_gap": 2.0 }
}
```

## 还留着的问题

1. **连线题 / 拖拽题 / 主观论述题**仍然无解 —— 这些不是「填一段文字」能解决的。
2. **数学题的正确率取决于模型**。AI 算错就是错，脚本不会自己验算；填空题没有选项可蒙。
3. **考试卷的风险比测验高**：期中期末一般只有一次机会，交卷前请确认 `submit_partial` 仍是 `false`。
4. **一个任务点里超过 3 段视频**时不会一次播完（`video_rounds` 上限），剩下的留给下一轮 —— 因为有的课真的会把整个学期的视频塞进一个任务点。
5. **页面源码认任务点依赖学习通现有的 class 名**（`ans-job-icon` / `ans-job-finished` / `unfinishCount`）。学校定制版页面如果改了这些名字，规则要跟着改。
