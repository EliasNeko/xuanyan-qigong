# v3.0.0 — 监视屏版：一条队列刷到底，卡住自己救

发布日期：2026-11-19

v2 系列解决的是「能不能把这一节做完」，v3 解决的是「一整门课、甚至好几门课，能不能不用管地
刷完，以及出问题时我能不能一眼看出它在哪儿卡住、它准备怎么救」。

于是多了一块**像系统监控一样的深色小屏**，直接嵌在主窗口右栏；多了一条 CLI 时代的写死流程
换成了「还没做完的小节按目录顺序排成一条队列」；也多了一套「自检 → 中文报错 → 自己救一次」。

## 为什么改

用户的四条原话大致是：

- 「进课之后先死等半分钟才进章节，别等了，直接进」
- 「目录上要能看出每一节还剩几个任务点，别让我自己数」
- 「视频看到一半弹出来的题，答错了你要自己换答案重答」
- 「我要看着它刷，得有个小监视屏，能看出现在在干什么、卡在哪、准备怎么救」

另外两个反复被提的点：**选课要能一次选好几门、按点的顺序排队**；**停止不要半路把视频扔下**。

## 改了什么

### 1. 进课直达章节（提速）

新版泛雅点开课程先落在「课程首页」（`fanyav3 / studentCourse`），那里没有章节树。
旧代码的做法是先死等 `.chapter_item` 三十秒，超时了再去点「章节」tab —— 用户看到的就是
「点开课以后卡很久」。`nav.py` 把这两件事合成一个轮询：**tab 一露头就点，章节树一渲染
出来立刻返回**；已经站在目录页上就直接读。

### 2. 任务点级目录状态

`tree.py` 从章节目录直接读每一节的「还剩几个任务点」：

```html
<input type="hidden" value="2" class="knowledgeJobCount">   <!-- 待完成任务点数 -->
<span class="catalog_points_yi">2</span>                   <!-- 黄色徽章里的数字 -->
```

读到的数字进队列（`need`），锁着的小节带 `.icon-chuangguan`，标成「锁定 · 可预约」。
读不到 `need` 的小节当成「至少还有 1 个」——**宁可白跑一趟，也不要把还剩一半的节当成做完**。

### 3. 只选终点：一条「还没做完」的队列

不再让用户勾起点 + 终点一堆小节。现在：**选几门课 → 抓取 → 队列里点一行 = 刷到这儿停**。

`plan.py` 把「多门课 → 每门课的目录 → 每个还差任务点的小节」摊成一条有序队列：

```
课1 → 课1 的目录顺序 → 课2 → 课2 的目录顺序 → …
```

每条 step 自带课程信息（`courseid / clazzid / cpi / course / no / sect / need / locked / chapterid`），
所以断点续跑时可以脱离「当前课程」单独执行。开始前会把「一共几个待完成任务点、终点之后
还有几个不刷」写在确认框里。

### 4. 视频弹题：答错了自己换答案重答

`quiz.py` 里提交后看判分：判错就把这次选过的选项记下来，换一组再答，最多重答 3 次，
每次换答案都写进日志（「答错了，换一个答案重答（第 2 次）」）。弹窗已经被学习通自己收起来
（判错但放行）时不再重答。同一道题被反复弹出来也不会无限循环 —— 返回题目指纹，外层认得出。

### 5. 监视屏：深色小屏，嵌在主窗口右栏

`monitor.py` 是一层**线程安全的快照字典**：后台线程往里写（`set / section / task / points /
video / problem`），界面每 0.4 秒读一次 `snap()`，谁也不用等谁（playwright 的 sync API 只能在
一个线程里用，界面不能直接去问它）。

`monitor_ui.py` 把它画成一块深色小屏：

- 正在刷哪门课 / 目录里的哪一节 / 这一节第几个任务点 / 它是什么类型
- 本节一共几个任务点，✓ 做完哪几个、还剩哪几个
- 视频看到几分几秒（百分比）
- 队列总进度：第几门课、第几节、第几个任务点
- 出了问题是什么原因、准备怎么救
- 最近几行动静

深色不是为了好看：浅色玻璃上放这么大的字会糊，深色底 + 亮字一眼能看清。这块屏可以直接
放成独立窗口（「放大监视屏」），也能拉到全屏；「查看总进度」按队列列出所有要刷的小节。

### 6. 自检与中文报错，然后自己救一次

`heartbeat.py` 知道「当前这一步是什么动作、正常要多久」，监视屏知道「上一次有动静是多少秒前」，
两下一凑就能分出「在思考」和「真卡死」。`guard.py` 把问题归成五类，各配一个动作：

| 问题 | 界面上的话 | 动作 |
| --- | --- | --- |
| `browser_closed` | 浏览器窗口被关掉了（或 Edge 自己崩了） | 重开浏览器，从这一节继续 |
| `net` | 网络断了 / 学习通连不上 | 等几秒、刷新页面再试 |
| `login` | 登录态失效了 | 重进课程；还不行就重新登录 |
| `page_changed` | 学习通页面改版了，脚本没认出这块内容 | 跳过这一节，先把能做的做完 |
| `stall` | 这一步卡住了，一直没有新动静 | 重新打开这一节，重读任务点 |

同一节连续 3 次没做完就先放着（`MAX_STALL`），自愈最多 2 次（`MAX_HEAL`），救不回来才停。
用户看到的永远是中文，不用看 traceback。

### 7. 停止 = 做完手上这个任务点

点「停止刷课」只是置一个旗子：脚本把当前这个任务点做完、复核它到底完成没有，然后才收工，
不会半路把视频扔下。监视屏上会写「收到停止：做完手上这个任务点就停」。

### 8. 顺手：app.py 拆成 app / app_run

PyArmor 试用版对**单个 `.py`** 有加密量上限（实测 33.5KB 单独加密就报 `out of license`），
app.py 到 v3 长到 33.5KB / 823 行。把「点开始之后发生的事」（起跑 / 停止 / 监视屏窗口 /
收工汇报）挪进 `learn_auto/app_run.py` 的 `AppRun` mixin，`App` 还是
`App(AppUI, AppHist, AppRun)` 一个类，只是方法分散在三个 mixin 里。app.py 回到 24KB。

## 附：v3 里为什么多了这么多模块

| 新模块 | 干什么 |
| --- | --- |
| `plan.py` | 把多门课的目录摊成一条有序队列（只收「还没做完」的小节） |
| `planrun.py` | 按队列执行：每步写监视屏、出错走 guard、停止做完当前任务点 |
| `tree.py` | 从章节目录读「每节还剩几个任务点」 |
| `nav.py` | 进课直达章节页（tab 与章节树合成一个轮询） |
| `monitor.py` | 线程安全的快照字典（后台写、界面每 0.4 秒读） |
| `monitor_ui.py` | 深色监视屏面板 / 独立窗口 / 总进度窗口 |
| `heartbeat.py` | 每步打点 + 每个动作的正常耗时 |
| `guard.py` | 停滞判定 + 中文报错 + 纠错动作 |
| `app_run.py` | 从 `app.py` 拆出的运行控制（PyArmor 单文件上限） |

## 升级

直接覆盖安装（或解压免安装包替换目录），`%LOCALAPPDATA%\LearnAuto` 里的登录态、题库、
进度、截图都保留。v2 的 `config.json` 直接能用，新加的字段会补默认值。

## 还留着的问题

- 监视屏是「看」用的，不能在里面手动点「重试 / 跳过」；要干预还是得点主窗口的按钮
- 讨论、问卷、直播类任务点不代做（识别出来并跳过）
- 填空 / 简答 / 计算靠模型现编，答得对不对看模型；连线、主观论述仍无解
- 闯关课一次只解锁一两个小节，队列里剩下的会等到解锁后接着刷（不是卡住）
- 同一节里如果有两个同类任务点（两个视频），任务点名重复时合并成一条显示
