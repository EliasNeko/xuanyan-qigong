# 整体架构与模块职责

## 一句话

一个进程里跑「界面线程 + 后台工作线程」，后台线程握着**一套** Playwright（Edge），按「用户排好的队列」一节一节往下做：进课直达章节 → 列任务点 → 按类型做（视频 / 文档 / 测验 / 填空简答）→ 复核完成 → 写监视屏快照。界面不碰 Playwright，只读快照；AI 答题另有一条专属线程，避免两套 sync Playwright 撞在同一个线程里。

## 一次完整运行的数据流

1. **启动** → 读 config.json → 建 Session（Edge 持久化上下文，profile 在本地）
2. **判登录**：三路取证——课程接口返回里有没有用户信息、cookie 里有没有 _uid、当前页面是不是个人空间
3. **选课** → 课程列表里点几门课（可多选，按点击的先后排队）
4. **抓取 → 队列**：每门课进目录（`nav.py` 把「点章节 tab」和「等树渲染」合成一个轮询，
   不再死等 30 秒），只收「还剩任务点」的小节，按目录顺序摊成一条队列；
   小节的 `need` 来自目录上的 `knowledgeJobCount` / 徽章数字，读不到按「至少 1 个」处理
5. **开始** → 队列里点一行 = 刷到这儿停（不点 = 全刷），确认框里写明一共几个待完成任务点
6. **执行**（`planrun.py`）：取队列下一步 → `nav` 直达这一节 → `taskpoint` 列出全部任务点 →
   按类型做（视频 / 文档 / 章节测验 / 填空·简答·计算 / 讨论）→ `tp_done` 复核这一个是否真做完 → 下一步
   - 完成判定不看「本节还剩几个」，只看「这一个」：页面三路信号 → 服务器未完成数的基线对比 → 本节归零
   - 视频播放循环每 3 秒自查一次，页面已经亮「任务点已完成」就停播收工
   - 每一步都往 `monitor` 写快照：哪门课、哪一节、第几个任务点、本节还剩什么、视频进度、队列进度
   - 出错 → `guard` 归成五类 → 中文写进监视屏 → 按动作救一次（重开本节 / 刷新 / 重进课程 / 跳过）
   - 停止 → 只置旗子：做完当前任务点、复核完成之后再收工
7. **记账**：progress.mark()、runstate.save()（上次跑到哪）、runstate.add_section()（刷课记录）
8. **收尾**：总结完成 / 待补 / 跳过 / 用时，界面弹小结

## 本地状态文件（都在 state/ 下，不进版本库）

| 文件 | 内容 |
| --- | --- |
| progress.json | 每节做到哪一步：done / partial / failed + attempts + 备注 + 时间 |
| run_state.json | 上次跑到哪个任务点、总任务点进度、时间（界面那行「上次跑到：…」） |
| run_history.json | 刷课记录：每节的视频结果、答题分数、评级（优秀/及格/不及格），留最近 300 条 |
| bank.sqlite | 本地题库（题干指纹 → 答案），跨课程复用 |
| shots/ | 答题截图、没过线时的批阅页 HTML dump（查错用） |
| browser_profile/ | Edge 的持久化 profile（登录态就在里面，绝不外传） |
| chat_profile/ | 豆包的持久化 profile |

## 为什么这么分

- **界面与业务分开**：业务在后台线程跑，界面只从队列取消息刷新，避免 Tk 卡死。
- **AI 单独一条线程**：Playwright 的 sync API 在一个线程里只能有一套；主线程已经有一套学习通的浏览器，再开第二套会抛「using Playwright Sync API inside the asyncio loop」。所以 AI 浏览器那条线程自己 `with sync_playwright() as pw:` 包住整个生命周期，其它线程通过队列 + Event 让它代跑。
- **状态落盘而非只在内存**：随时关窗口都不丢进度；重开就从「上次跑到哪」接着来。
